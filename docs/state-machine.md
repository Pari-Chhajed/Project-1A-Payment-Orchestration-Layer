# Payment State Machine

```mermaid
stateDiagram-v2
  CREATED --> ROUTE_SELECTED
  CREATED --> ABANDONED
  ROUTE_SELECTED --> AUTH_INITIATED
  AUTH_INITIATED --> AUTHORISED
  AUTH_INITIATED --> AUTH_FAILED
  AUTH_INITIATED --> AUTH_TIMEOUT
  AUTH_INITIATED --> CAPTURED
  AUTH_INITIATED --> AUTH_EXPIRED
  AUTH_FAILED --> ROUTE_SELECTED
  AUTH_TIMEOUT --> ROUTE_SELECTED
  AUTHORISED --> CAPTURE_INITIATED
  AUTHORISED --> VOID_INITIATED
  CAPTURE_INITIATED --> CAPTURED
  CAPTURE_INITIATED --> PARTIALLY_CAPTURED
  CAPTURE_INITIATED --> CAPTURE_FAILED
  CAPTURED --> SETTLEMENT_PENDING
  CAPTURED --> REFUND_INITIATED
  SETTLEMENT_PENDING --> SETTLED
  SETTLEMENT_PENDING --> SETTLEMENT_FAILED
  SETTLED --> REFUND_INITIATED
  REFUND_INITIATED --> REFUNDED
  REFUND_INITIATED --> PARTIALLY_REFUNDED
  CAPTURED --> RECONCILIATION_REQUIRED
  RECONCILIATION_REQUIRED --> MANUAL_REVIEW
```

Additional advanced states include `AUTH_PENDING`, `CAPTURE_PENDING`, `SETTLEMENT_FAILED`, `DISPUTED`, `CHARGEBACK`, `REVERSED`, `WEBHOOK_PENDING`, and `RECONCILIATION_REQUIRED`.

Every accepted, rejected, and duplicate no-op transition is recorded in `transaction_state_log`.
