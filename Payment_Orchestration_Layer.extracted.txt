In

A2.1  Why  State  Machines  Are  Non-Negotiable  in  Payments  Consider  a  naive  implementation  where  transaction  status  is  stored  as  a  simple  string  column  that  
can

to

to

  A  properly  implemented  state  machine  prevents  this  by  enforcing  that  transitions  can  only  occur

   Score(gateway)  =   (W_success  *  NormalizedSuccessRate(gateway))  +  (W_latency  *  (1  -  NormalizedLatency(gateway)))  +  (W_cost     *  (1  -  NormalizedCost(gateway)))  +  (W_health   *  HealthScore(gateway))  +  (W_fit      *  FitScore(gateway,  payment_method))    Where:  NormalizedSuccessRate  =  success_count  /  total_count   (in  sliding  window)  NormalizedLatency  =  (p95_latency  -  min_latency)  /  (max_latency  -  min_latency)  NormalizedCost  =  (gateway_cost  -  min_cost)  /  (max_cost  -  min_cost)  HealthScore  =  1.0  (healthy),  0.5  (degraded),  0.0  (down)  FitScore  =  1.0  (supported),  0.0  (not  supported)
